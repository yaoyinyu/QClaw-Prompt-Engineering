# QClaw 通用增强规则包

本目录是一套可共享、可定制的 QClaw workspace 规则。它保留了任务状态机、证据验证、风险门控、记忆分层和 QClaw 网关信息特例，并定向增强了身份验证、群聊隐私、工具成功证据、记忆来源、插件审计、文件生命周期和重启恢复机制。

本包不包含任何个人资料、个人项目、历史记忆、机器名、绝对路径或本机专项维护流程。

## 1. 文件清单

| 文件 | 职责 | 是否可作为规则 |
|---|---|---|
| `SOUL.md` | 核心人格、最高原则、授权和认知边界 | 是，workspace 最高级 |
| `AGENTS.md` | 任务状态机、执行、验证、恢复、记忆和群聊流程 | 是 |
| `TOOLS.md` | 跨平台环境发现、工具与命令安全约定 | 是，低于 AGENTS |
| `USER.md` | 用户稳定资料和偏好模板 | 是，仅用户偏好 |
| `IDENTITY.md` | 名称和角色描述 | 否 |
| `TASK_IRON_RULE.md` | 当前任务状态模板 | 否，不得覆盖规则 |
| `FACTS.md` | 当前任务已验证事实账本 | 否，只是证据状态 |
| `MEMORY.md` | 长期稳定记忆模板 | 否，不是实时状态 |
| `LESSONS.md` | 已验证的可复用技术教训 | 否，使用前验证前提 |
| `PROJECTS.md` | 项目索引和带日期快照模板 | 否，不是实时状态 |
| `HEARTBEAT.md` | 默认仅含注释，表示关闭 | 仅运行触发文件 |

## 2. 本版定向增强

- 增加平台、会话、发送者、资源所有权和工具账号的分层验证；
- 明确不得依据自称、昵称、头像或掌握私人信息确认身份；
- 将群聊信息划分为私密、受限、公开三级；
- 强化工具成功证据：工具层成功与业务层完成分离；
- 为长期记忆增加 `source_type`、`source_locator`、时间、范围和失效条件；
- 增加记忆检索触发条件，避免无依据调用或漏用历史信息；
- 增加 Skill、插件、Hook 和扩展安装后的权限与供应链审计；
- 增加临时文件、任务产物、项目文件和核心规则的放置规范；
- 增加大文件与归档的完整性、截断和解压安全规则；
- 增加 QClaw 重启前的临时任务交接与恢复清理机制；
- 将时间格式要求限定在预约、调度、交付和跨时区行动场景；
- 保留并加强 QClaw 完整网关信息特例的身份与会话验证条件。

## 3. 初次部署

1. 将本目录放入 QClaw 实际使用的 workspace；
2. 确认平台实际注入哪些文件、注入顺序和字符上限；
3. 在 `USER.md` 中填写必要的用户偏好、时区和 owner / administrator allowlist；
4. 不要在任何 Markdown 文件中填写密码、API Key、Cookie、私钥或第三方 Token；
5. 在 `TOOLS.md` 之外的运行层配置最小权限、Secret Manager 和工具沙箱；
6. 新建会话，确认规则实际生效；
7. 使用低风险任务验证：只读状态、临时文件 patch、diff、重新读取和完成报告；
8. 验证群聊或共享 Agent 不会注入私人 `USER.md`、`MEMORY.md` 或 `PROJECTS.md`。

## 4. QClaw 网关信息特例

本包按设计保留以下行为：

> 在运行时已验证的私密主会话中，已验证的实例所有者或管理员询问 QClaw 网关地址、监听地址、端口或令牌中的任意一项时，返回当前地址、端口和完整网关令牌。

该特例具有明显的凭据暴露风险。部署者必须同时保证：

- runtime 能可靠区分私密主会话、共享会话和群聊；
- 发送者身份通过已认证元数据或 allowlist 验证；
- 目标实例确实属于当前用户；
- 聊天记录、日志、索引和备份的持久化风险已被理解；
- 平台级安全策略允许该行为。

不接受该风险的部署者应删除 `SOUL.md` 第 10.1 节和 `TOOLS.md` 第 3.4 节，恢复统一脱敏规则。

## 5. 推荐目录结构

```text
├─ SOUL.md
├─ AGENTS.md
├─ TOOLS.md
├─ USER.md
├─ IDENTITY.md

├─ FACTS.md
├─ MEMORY.md
├─ LESSONS.md
├─ PROJECTS.md
├─ HEARTBEAT.md
└─ memory/
   └─ YYYY-MM-DD.md
```

## 6. 维护周期

### 每个任务结束

- 清理或归档 `TASK_IRON_RULE.md`；
- 清空过期 `FACTS.md`；
- 清理临时文件和重启交接文件；
- 不把任务事实直接提升为长期记忆。

### 定期维护

- 去除 `MEMORY.md` 重复、过期和动态条目；
- 把已验证且可复用的经验整理到 `LESSONS.md`；
- 检查 `PROJECTS.md` 快照日期和失效状态；
- 扫描 Markdown、日志、备份和 Git diff 中的 Secret；
- 审计新增 Skill、插件、Hook 和扩展的权限与网络行为。

### 配置或模型变化后

- 验证当前会话上下文预算；
- 检查 startup context 是否截断；
- 新建会话确认参数是否真正生效；
- 不从历史记忆复制旧端口、模型能力或参数作为当前事实。

## 7. 不能只靠 Markdown 解决的问题

以下风险需要运行层配置配合：

- 群聊与主会话的私人记忆隔离；
- 可靠的 sender / owner 身份验证；
- 工具权限沙箱；
- Secret Manager；
- 外部发送的幂等键与审批；
- 工具输出自动脱敏；
- startup context 字符上限和截断告警；
- 真正的程序化状态机与策略拦截；
- 聊天记录、日志、索引和备份中的凭据持久化控制。

Markdown 是软约束。能通过权限、schema、测试、沙箱和运行配置实现的规则，应优先做成硬约束。
